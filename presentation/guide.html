00

En une phrase

On a construit une API web qui reçoit un article (titre + texte) et renvoie sa catégorie — politique, économie, sport, culture, faits_divers — avec un score de confiance et le temps de calcul, le tout packagé dans Docker et couvert par des tests.

01

Le contexte et le problème

MédiaLens voulait classer ses articles automatiquement. Un dev, Adrien, avait entraîné un très bon modèle (un CamemBERT « fine-tuné », macro-F1 ≈ 0.87)… mais il est parti sans laisser les poids du modèle (pytorch_model.bin, ~443 Mo). On a donc son plan (config, tokenizer, notebook) mais pas le cerveau entraîné.

Les contraintes de la CTO

  • Un endpoint POST /infer : entrée {titre, texte} → sortie {categorie, score, latence_ms}.
  • Latence < 500 ms pour 99 % des requêtes (p99 < 500 ms) — un « SLA ».
  • Un endpoint GET /health qui dit si le modèle est chargé.
  • Le tout sous Docker, lançable en une seule commande.

Le vrai défi : produire un classifieur correct sans réentraîner (pas le temps, données incomplètes), tout en tenant le SLA de latence.

02

La décision centrale : le « zero-shot »

Pourquoi zero-shot ?

Sans les poids, réentraîner était exclu (trop long, données absentes). On a choisi le zero-shot : classer un texte dans des catégories que le modèle n'a jamais apprises spécifiquement. On lui donne le texte + la liste des étiquettes, il évalue laquelle « colle » le mieux.

Techniquement, ça repose sur du NLI (Natural Language Inference) : le modèle juge si une phrase B découle d'une phrase A. On détourne cette capacité — A = l'article, B = « Cet article parle de sport » (une hypothèse par catégorie) — et on garde l'hypothèse la mieux notée.

Le modèle retenu : mDeBERTa-v3

CritèreDétail
Latence~280M paramètres → tient le SLA : p99 = 343 ms.
Français natifentraîné sur XNLI (français inclus), pas une traduction.
Légerimage Docker plus contenue qu'un gros modèle.
Zero-shot prêtaucun fine-tuning, aucun corpus d'entraînement requis.

Le réglage qui change tout

Par défaut, l'hypothèse est construite en anglais (« This example is {} »). En la passant en français (« Cet article parle de {} ») avec des étiquettes lisibles, on gagne +8 points de F1 (0.636 → 0.713) — mesuré sur 3 configurations via scripts/evaluate.py.

03

Comment fonctionne l'inférence

Fichier : app/inference.py.

  1. Construction de l'entrée (build_input) : on concatène titre + ". " + texte, tronqué à 1024 caractères (borne la latence). Concaténer titre et texte améliore la qualité (+3 pts de F1 selon Adrien).
  2. Chargement du modèle (load_model) : chargé une seule fois et gardé en cache (lru_cache) — jamais rechargé par requête.
  3. Prédiction (predict) : on soumet le texte + les 5 étiquettes françaises + le gabarit FR ; on prend le meilleur score ; on re-mappe l'étiquette lisible (« économie ») vers l'étiquette canonique (« economie ») ; on mesure latence_ms.
04

L'API (FastAPI)

Fichier : app/main.py.

  • POST /infer — reçoit {titre, texte}, renvoie {categorie, score, latence_ms}. Validation par Pydantic : si texte est vide/absent → HTTP 422 automatique.
  • GET /health — renvoie {"status":"ok","model_loaded":true}.
  • GET / — métadonnées du service (catégories, endpoints).

Le « lifespan »

Le modèle est chargé au démarrage du serveur (pas à la première requête). Résultat : /health reflète le vrai état, et la première requête /infer n'est jamais pénalisée par le temps de chargement.

07

Lancer et tester l'API

Toutes les commandes se lancent depuis la racine inferloop-j1/.

1 · Lancer en local

.venv/bin/python -m uvicorn app.main:app --port 8000

Attendre Application startup complete (~10 s, chargement du modèle).

Interface de test — /app/

Une fois l'API lancée, ouvre http://127.0.0.1:8000/app/ : un frontend cliquable servi par l'API (voyant de santé, 5 exemples pré-remplis, catégorie + score + latence). La façon la plus simple de tester, sans ligne de commande.

2 · Tester via Swagger

Ouvrir http://127.0.0.1:8000/docs → déplier POST /infer → Try it out → coller un article → Execute. La réponse (code 200 + JSON) s'affiche sous Server response.

3 · Tester via curl

curl -X POST http://127.0.0.1:8000/infer \
  -H "Content-Type: application/json" \
  -d '{"titre":"Les Bleus en finale","texte":"L equipe de France s est qualifiee 2-1."}'

curl http://127.0.0.1:8000/health

4 · Tests automatiques & validation

.venv/bin/python -m pytest tests/ -v        # 8 tests
.venv/bin/python -m scripts.evaluate        # recalcule accuracy / F1
.venv/bin/python -m scripts.benchmark       # latence p50/p95/p99 (preuve SLA)

5 · Avec Docker (comme en prod)

docker compose up --build

Le modèle est téléchargé pendant le build : le conteneur démarre ensuite sans réseau et /health passe ok en quelques secondes.

08

Limites connues & suites (Jour 2)

  • Écart au fine-tuné : ~15 pts de F1 sous le modèle d'Adrien — inhérent au zero-shot. Regagnables avec les vrais poids ou un fine-tuning.
  • economie sous-détectée (recall 0.31) : piste = étiquettes ciblées ou du few-shot.
  • Articles courts (< 50 mots) moins fiables — déjà signalé par Adrien.
  • Pas de monitoring de drift : aucune détection de dérive sur les articles récents.
  • Image Docker lourde (torch + modèle) — atténuée par le wheel CPU-only et le .dockerignore.
09

Glossaire

Fine-tuning
Réentraîner un modèle existant sur un jeu de données précis pour le spécialiser. Le modèle d'Adrien l'était ; le nôtre non.
Zero-shot
Classer sans avoir appris les catégories au préalable.
NLI
Natural Language Inference : juger si une phrase découle d'une autre. La base technique du zero-shot ici.
CamemBERT / mDeBERTa
Des modèles de langage (type BERT) ; mDeBERTa est multilingue et sait le français nativement.
Tokenizer
Découpe le texte en unités (tokens) que le modèle comprend.
Gabarit d'hypothèse
La phrase modèle qui transforme une étiquette en hypothèse (« Cet article parle de {} »).
F1 / macro-F1
Mesure combinant précision et rappel. « Macro » = moyenne des F1 par classe (chaque classe compte pareil).
Precision / Recall
Précision : parmi les prédits « sport », combien le sont vraiment. Rappel : parmi les vrais « sport », combien ont été trouvés.
Accuracy
Proportion de prédictions correctes, toutes classes confondues.
Latence · p50 / p95 / p99
On trie les mesures, de la plus rapide à la plus lente. p50 (médiane) = le cas typique, la moitié des requêtes font mieux ; p95 = seules 5 % dépassent ; p99 = quasi le pire cas, 1 requête sur 100 dépasse. Le SLA vise le p99 (pas la moyenne) pour garantir la rapidité même dans les cas lents.
SLA
Service Level Agreement : engagement de niveau de service ; ici « p99 < 500 ms ».
Endpoint
Une URL de l'API qui rend un service (/infer, /health).
Pydantic
Librairie qui valide le format des données entrantes (et renvoie 422 si invalide).
Lifespan
Mécanisme FastAPI pour exécuter du code au démarrage/arrêt du serveur (ici : charger le modèle une fois).
Docker · image / conteneur
Docker empaquette l'app + ses dépendances dans une « image » ; un « conteneur » est une instance qui tourne.
CPU-only (torch)
Version de PyTorch sans les librairies GPU (CUDA), plus légère, suffisante ici.
